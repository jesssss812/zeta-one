# Hackathon requirements

AITX & MLOps World Community Hackathon at Austin Tech Week, Oct 26–30, 2026. In person at Antler
VC (800 Brazos St #340, Austin) or remote. Copied from the organizers' Notion page and its
submission checklist on 2026-10-27; check the
[Notion page](https://common-scooter-829.notion.site/AITX-MLOps-World-Community-Hackathon-Austin-Tech-Week-4021e636288e81e08278fd9a977d7639)
for changes before relying on a detail.

| When | What |

| **Thu Oct 29, 5:00 PM CT** | **Submissions close.** One submission per team |

## Tracks

Pick one: AutoHDR (image models and pipelines), **Rho (fintech)**, Antler (agents), or Open.
Zeta One is aimed at the Rho track, though the track isn't final until submission: "money movement, finance automation, or tools that make running a
company's finances less painful". The Antler track asks for agents or agent tooling that do real
work end to end.

## Submission checklist

Submitted through the [Airtable form](https://airtable.com/appWQWPtBqDUhCPPj/shrrmEvRZGqjYRIN3).

- Project title
- Track
- 2–5 minute demo video, **recorded with Loom**, showing the core loop live
- Public repo link. The README must include:
  - quick start (commands to run)
  - tech stack and architecture diagram (simple is fine)
  - how to reproduce the demo (env vars, API keys, sample `.env`)
  - any datasets or synthetic data used, and their provenance
  - known limitations and next steps
- Deployed URL, or a short screen capture of the working app
- Team roster: names, roles, contacts
- Short write-up, 150–300 words: problem → who it helps → solution → impact

## Judging

Judges score the live Hack Fair demo, the demo video and the codebase. They are "judging real,
working systems, not slide decks or simple API wrappers".

| Area | Criteria |
| --- | --- |
| Technical execution and completeness | Completeness: the core workflow runs without crashing. Technical depth: real engineering, a complex pipeline rather than a basic wrapper |
| Value and impact | Insight quality: output that is non-obvious and genuinely useful. Usability: a real user could act on it tomorrow |
| Innovation and execution | Creativity: tools or data combined in a novel way; the product looks and feels good. Performance: optimized for speed or scale |
