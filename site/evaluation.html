How Zeta One is evaluated

How the evaluation is made, labelled, run and reported

Every configuration of the engine is scored on the same labelled cases, so the trade between fraud caught, honest payments held up and model spend can be compared. Each box is one step, coloured by who does it. Code runs every step that has to be repeatable. Models write case text, label blind and are the system under test. A person makes the judgement calls the score depends on.

PersonHuman judgement, never handed to a model.
Model-assistedClaude drafts; a person edits and decides.
ModelA model does it alone, under rules code enforces.
CodeDeterministic and repeatable; no model involved.

How the cases are built

Each generated case is one combination of eight dimensions, each with a few values. Code builds every combination and drops the ones that can't happen, such as a bank change older than the vendor, or invoice text on a case with no bill. A model only writes the words. Whether a case is fraud follows from where the money would go: it is payee fraud only when the payment would reach someone other than the real vendor.

Harmless look-alikes are built in on purpose: honest urgent invoices, confirmed bank changes and real change notices, so a warning sign alone is never the answer. Because the dimensions resemble the rules' own features, the hand-written hard set, which comes from none of them, is the headline.

Where the methods come from

The method follows published practice for evaluating AI systems, adapted to a decision that code can grade.

What keeps the scores honest

Each safeguard is enforced by code or recorded with the results, not left to good intentions.

Tuned on dev, scored on test

  • Separate seeds and separately written wordingtest shares only the routine combinations dev had too few of
  • test is frozen and hashed before scoringa run refuses a set that changed, or an unfrozen test
  • The rules' lexicon was fixed before test was writtenthe wording model never saw it

The hard set is the headline

  • Generated cases resemble the rules' featuresso the rules would look near-perfect on them
  • 15–20 cases written by hand, outside the generatorunfamiliar impersonation, subtle injection, honest urgency

Labels are blind and checked

  • The AI labeller never sees the truthonly what the engine sees, plus the guide
  • A person labels 40 test cases blindagreement reported as Cohen's κ with a 95% interval
  • The person settles every disagreementeach case records where its label came from

Friction counts as much as fraud

  • Unneeded challenges sit beside the catch rateand the two baselines bound the trade
  • Cost per 1,000 decisions for every configurationeach result row records its model calls and cost

All cases are synthetic, so no rate in the report is a production rate. Payments are simulated throughout. The method in full: evaluation.md. The latest results: report.md.
